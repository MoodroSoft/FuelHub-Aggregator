# Архитектура и структура проекта

Этот документ описывает, как устроен проект, из каких слоёв он состоит и за что отвечает каждая директория. Понимание архитектуры — ключ к эффективной работе с кодом.

---

## 🏛️ Архитектура: Классический трёхслойный подход

Проект построен по принципам **многослойной архитектуры**. Это означает, что код разделён на независимые слои, каждый со своей зоной ответственности. Это делает приложение гибким, тестируемым и простым в поддержке.

![Layered Architecture](/img/layer-arch.png)
*Примерная схема слоёв* 

Движение данных идёт строго сверху вниз: `API` вызывает `Логику`, а `Логика` обращается к `Репозиторию`.

### 1. Слой представления (Presentation Layer) — `src/api`

Это верхний уровень, точка входа в наше приложение. Его задача — общаться с внешним миром по протоколу HTTP.

- **Что делает:** Принимает HTTP-запросы, проверяет их корректность (с помощью схем Pydantic) и передаёт управление слою бизнес-логики.
- **Ключевые технологии:** **FastAPI**.
- **Состав:**
    - **Views (`views/`):** Функции, которые обрабатывают эндпоинты (например, `get_gas_stations`).
    - **Schemas (`schemas/`):** Pydantic-модели, которые описывают данные для запросов и ответов. Они отвечают за валидацию и сериализацию.
    - **Router (`router.py`):** Собирает все эндпоинты в единый роутер для подключения к приложению.

### 2. Слой бизнес-логики (Business Logic Layer) — `src/logic`

Это "мозг" нашего приложения. Здесь содержится основная бизнес-логика, которая не зависит от деталей реализации (как именно мы получаем данные или как мы их храним).

- **Что делает:** Оркестрирует выполнение задач. Например, сервис агрегации данных (`DataAggregatorService`) запрашивает данные из репозиториев, обрабатывает их, разрешает конфликты и возвращает результат.
- **Ключевые особенности:** Этот слой ничего не знает про HTTP, FastAPI или SQLAlchemy. Он работает с чистыми Python-объектами.

### 3. Слой доступа к данным (Data Access Layer) — `src/repositories`

Это самый нижний уровень, который отвечает за всё взаимодействие с базой данных. Он реализует **паттерн "Репозиторий"**.

- **Что делает:** Предоставляет простые методы для работы с данными (например, `create`, `get_by_id`, `find_in_radius`). Он скрывает (инкапсулирует) всю сложность SQL-запросов.
- **Ключевые технологии:** **SQLAlchemy**.
- **Особенности:** Если мы решим поменять базу данных с PostgreSQL на что-то другое, изменения коснутся только этого слоя. Бизнес-логика и API останутся нетронутыми.

### Сквозные компоненты (Cross-Cutting Concerns)

- **Модели (`src/models.py`):** SQLAlchemy-модели, описывающие таблицы в базе данных. Используются в основном слоем репозиториев.
- **Зависимости (`src/dependencies`):** Система **Dependency Injection** (внедрение зависимостей) от FastAPI. Это "клей", который связывает слои вместе. Например, он создаёт экземпляр репозитория и передаёт его в функцию бизнес-логики, а ту, в свою очередь, — в эндпоинт API.
- **Фоновые задачи (`src/tasks`):** Логика, которая выполняется вне основного потока приложения (например, по расписанию). Задачи обычно вызывают функции из слоя бизнес-логики.

## 📁 Структура директорий

```
fuelhub-aggregator/
├── .env                # Локальные переменные окружения (не для Git)
├── docker-compose.yml  # Описание сервисов для локального запуска
├── Dockerfile          # Инструкция по сборке Docker-образа приложения
├── pyproject.toml      # Зависимости проекта (для менеджера uv)
├── README.md           # Главная документация
│
├── docs/               # Директория с этой и другой документацией
│   ├── Архитектура проекта.md
│   └── ...
│
├── src/                # Основной исходный код приложения
│   ├── alembic.ini       # Конфигурация Alembic для миграций
│   ├── main.py           # Главный файл, создающий и запускающий FastAPI приложение
│   ├── models.py         # Декларативные модели SQLAlchemy
│   │
│   ├── api/              # Слой представления (API)
│   │   └── v1/             # Версия 1 нашего API
│   │       ├── router.py   # Главный роутер v1
│   │       ├── schemas/    # Pydantic-схемы
│   │       └── views/      # Эндпоинты API
│   │
│   ├── core/             # Ядро приложения: базовые настройки
│   │   ├── config.py     # Конфигурация (чтение переменных окружения)
│   │   ├── database.py   # Настройка сессий для подключения к БД
│   │   └── migrations/   # Директория с файлами миграций Alembic
│   │
│   ├── dependencies/     # Настройка системы внедрения зависимостей
│   │
│   ├── logic/            # Слой бизнес-логики
│   │
│   ├── repositories/     # Слой доступа к данным (репозитории)
│   │
│   └── tasks/            # Фоновые задачи (Celery)
│
└── tests/              # Автоматические тесты
```
