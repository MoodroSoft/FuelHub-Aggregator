# Критерии оценки задания

🚩 - обязательно для выполнения минимальных критериев

✅ - критерии для высокой оценки


## 1. Качество кода (Code Quality)
- 🚩 **Архитектура:** Продуманная и масштабируемая архитектура приложения. Корректное разделение на слои (например, `api`, `logic`, `repositories`).
- 🚩 **Чистота и читаемость:** Код должен быть легко читаемым, хорошо структурированным и следовать принципам чистого кода.
- ✅ **Стиль кода:** Соответствие стайлгайдам (PEP 8 для Python).
- ✅ **Отсутствие дублирования:** Минимизация повторения кода (принцип DRY).

## 2. Документация (Documentation)
- 🚩 **Комментарии в коде:** Наличие ясных и полезных комментариев там, где это необходимо (объяснение сложной логики).
- 🚩 **README.md:** Информативный `README.md` с описанием проекта, инструкциями по установке и запуску.
- ✅ **Docstrings:** Наличие docstrings для всех модулей, классов, функций и методов.

## 3. Тестирование (Testing)
- 🚩 **Покрытие API тестами:** Все API-методы должны быть покрыты хотя бы частично тестами.
- ✅ **Покрытие тестами Celery-задач:** Все Celery-задачи должны быть покрыты тестами с проверкой их выполнения (например изменение записи в базе данных).
- ✅ **Качество тестов:** Тесты должны быть атомарными, независимыми и проверять как позитивные, так и негативные сценарии.

## 4. Функциональность (Functionality)
- 🚩 **Соответствие [требованиям](Конечный%20результат.md):** Реализация всего заявленного в задании функционала.
- 🚩 **Корректность работы:** Отсутствие багов и ошибок в работе приложения.
- ✅ **Производительность:** Оптимальная производительность и отсутствие узких мест: оптимизированные запросы к базе данных, кэширование и другие оптимизации.

## 5. Git и управление версиями (Version Control)
- 🚩 **Коммиты:** Атомарные и информативные коммиты. Сообщения коммитов должны быть написаны в едином стиле.
- ✅ **Ветки:** Грамотное использование веток для разработки нового функционала и исправления ошибок (поэтому не советуем удалять ветки после приянтия Pull Request'а).


> Справка
>
> Вы, конечно, можете использовать ИИ в ходе выполнения задачи,
> но стоит быть готовым ответить на вопросы тех. специалиста по вашей реализации того или иного функционала, если планируете выполнить задание на высокую оценку.
