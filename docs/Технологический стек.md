# Технологический стек проекта

В этом файле собран список всех ключевых технологий, которые используются в проекте. Рядом с каждой технологией есть краткое описание её роли и ссылка на официальную документацию. Используйте эти ссылки как основной источник информации при изучении.

---

## Основной фреймворк

### FastAPI

- **Роль в проекте:** Основа всего веб-приложения. Это современный и очень быстрый веб-фреймворк для создания API. Он отвечает за обработку HTTP-запросов, роутинг, валидацию данных и автоматическую генерацию документации.
- **[Официальная документация](https://fastapi.tiangolo.com/)**

---

## Работа с данными

### Pydantic

- **Роль в проекте:** Валидация, сериализация и управление настройками. Pydantic позволяет определять структуру данных с помощью Python-классов. FastAPI использует его "под капотом" для проверки всех входящих и исходящих данных.
- **[Официальная документация](https://docs.pydantic.dev/latest/)**

### PostgreSQL

- **Роль в проекте:** Основная реляционная база данных. Здесь хранятся все наши данные: информация об АЗС, видах топлива, услугах и т.д.
- **[Официальная документация](https://www.postgresql.org/docs/)**

### SQLAlchemy

- **Роль в проекте:** ORM (Object-Relational Mapper) для работы с PostgreSQL. SQLAlchemy позволяет нам взаимодействовать с базой данных, используя Python-классы (модели) вместо написания сырых SQL-запросов. Это делает код более читаемым и безопасным.
- **[Официальная документация](https://www.sqlalchemy.org/)**

### Alembic

- **Роль в проекте:** Инструмент для управления миграциями базы данных. Когда мы меняем наши SQLAlchemy-модели (например, добавляем новую колонку в таблицу), Alembic генерирует скрипты для безопасного обновления структуры базы данных без потери данных.
- **[Официальная документация](https://alembic.sqlalchemy.org/en/latest/)**

## Фоновые задачи и кэширование

### Celery

- **Роль в проекте:** Система для выполнения отложенных и периодических задач. Мы используем Celery для запуска долгих процессов в фоне, таких как сбор данных с внешних источников, чтобы основной API не "тормозил" в ожидании их завершения.
- **[Официальная документация](https://docs.celeryq.dev/en/stable/)**

### Redis

- **Роль в проекте:** У Redis две ключевые роли:
    1.  **Брокер сообщений для Celery:** Redis выступает в качестве "посредника", через которого Celery получает информацию о том, какие задачи нужно выполнить.
    2.  **Кэш:** Мы используем Redis для кэширования часто запрашиваемых данных, чтобы ускорить ответы API.
- **[Официальная документация](https://redis.io/documentation)**

## Инструменты и окружение

### Python

- **Роль в проекте:** Язык программирования, на котором написан весь бэкенд.
- **[Официальная документация](https://docs.python.org/3/)**

### Docker и Docker Compose

- **Роль в проекте:** Технологии контейнеризации. Docker позволяет "упаковать" наше приложение и все его зависимости (базу данных, Redis и т.д.) в изолированные контейнеры. Docker Compose позволяет управлять запуском и связью всех этих контейнеров одной командой. Это обеспечивает идентичность окружения на машине любого разработчика и на сервере.
- **[Документация Docker](https://docs.docker.com/)**
- **[Документация Docker Compose](https://docs.docker.com/compose/)**

### uv

- **Роль в проекте:** Менеджер пакетов и виртуальных окружений. Это очень быстрый инструмент, который мы используем для установки и управления Python-библиотеками, перечисленными в `pyproject.toml`.
- **[Документация на GitHub](https://github.com/astral-sh/uv)**

### Pytest

- **Роль в проекте:** Фреймворк для написания и запуска автоматических тестов. Тестирование — неотъемлемая часть качественной разработки.
- **[Официальная документация](https://docs.pytest.org/en/latest/)**

### Nginx

- **Роль в проекте:** Веб-сервер и reverse-proxy. На "боевом" сервере Nginx будет стоять перед нашим FastAPI-приложением, принимая на себя весь входящий трафик, раздавая статические файлы и перенаправляя запросы к приложению.
- **[Официальная документация](https://nginx.org/ru/docs/)**
